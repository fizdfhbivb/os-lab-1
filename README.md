# Лабораторная работа №1 по операционным системам

Верижников Владислав Павлович, группа М8О-210БВ-25. Вариант 5.

## Условие

Родитель создаёт дочерний процесс. Первой строкой вводится имя выходного файла,
которое передаётся ребёнку при запуске. Далее вводится по одному целому числу
в строке. Родитель передаёт строки через pipe1, связанный со стандартным входом
ребёнка. Ребёнок проверяет числа на простоту: составные записывает в файл,
а при простом или отрицательном числе оба процесса завершаются. Обратный
канал pipe2 передаёт подтверждения. Родитель и ребёнок — разные программы.

Решение предназначено для Linux и написано на C11, без комментариев в коде.
Прикладной ввод-вывод и управление процессами выполняются через системные
интерфейсы: read, write, open, close, pipe, fork, dup2, execv, waitpid,
sigaction, readlink, _exit. stdio.h, threads.h, stdatomic.h, библиотека C++,
printf, scanf, fopen, malloc и atoi не используются. Стандартный стартовый
код компилятора обеспечивает вход в main; execv — разрешённая в задании
вариация семейства exec.

## Сборка и запуск в Linux

Нужны компилятор C (GCC или Clang) и make. Для тестов дополнительно нужен
Python 3.9 или новее без внешних пакетов.

Из корня проекта в Linux-терминале:

```sh
make
./build/parent
```

Пример ввода:

```text
result.txt
4
6
9
7
```

На числе 7 оба процесса завершаются. Выходной файл:

```text
4
6
9
```

Чтобы посмотреть результат:

```sh
cat result.txt
```

Запуск из файла:

```sh
printf 'result.txt\n4\n6\n9\n7\n' | ./build/parent
```

Без make:

```sh
mkdir -p build
cc -std=c11 -Wall -Wextra -Wpedantic -Werror -O2 src/parent.c -o build/parent
cc -std=c11 -Wall -Wextra -Wpedantic -Werror -O2 src/child.c -o build/child
```

parent и child должны находиться в одной папке. Родитель находит ребёнка
через /proc/self/exe, поэтому текущая рабочая папка может быть другой.
/proc должен быть смонтирован, как в обычной Linux-системе.

Это исходники для Linux. В Windows они запускаются внутри уже настроенной
Linux-среды, например WSL или виртуальной машины, а не как программы .exe.
Программа больше не вызывает CreateProcessW и не запускает Windows child.exe.

## Поведение

- Диапазон чисел: от −2147483648 до 2147483647. Разрешены знак и окружающие
  ASCII-пробелы. В строке должно быть одно число.
- 0 и 1 пропускаются: они не простые и не составные. Это уточнение случая,
  который не описан в условии.
- Простые и отрицательные числа не записываются и завершают оба процесса.
- EOF завершает работу; последняя строка без LF обрабатывается.
  Дополнительная команда exit позволяет завершить интерактивный запуск.
- Пустая команда, неверное число, переполнение или слишком длинная строка
  завершают работу с кодом 1. Уже записанные числа сохраняются.
- Для простоты используются массивы на 4096 байт. Максимальная длина строки
  до LF — 4095 байт, включая CR при CRLF. Более длинная строка отклоняется,
  а не обрезается. Это ограничение подходит для ввода одного числа.
- Имя файла вводится без обрамляющих кавычек; пробелы и кириллица поддерживаются.
  Относительный путь считается от текущей папки. Каталог должен существовать;
  существующий файл перезаписывается. Нулевой байт в имени запрещён.
- pipe2 передаёт один байт: R — файл открыт, C — команда обработана,
  S — остановка по условию, E — ошибка. Служебные байты не печатаются.
- Родитель ждёт ответ после каждой команды. После остановки ребёнка
  следующий ввод пользователя не требуется.
- SIGPIPE игнорируется через sigaction, поэтому разрыв канала возвращает
  ошибку записи, которую можно обработать. read, write и waitpid повторяются
  при EINTR. Неиспользуемые концы каналов закрываются.
- Проверка простоты перебирает делители от 2 до √n; условие d <= n / d
  исключает переполнение d*d.
- Код 0 означает штатное завершение, 1 — ошибку. Диагностика с errno
  поступает в stderr, составные числа — только в файл.

## Тестирование

```sh
make test
```

Или после сборки:

```sh
python3 tests/test_lab.py
```

Подготовлены 23 сценария: составные, простые, отрицательные числа, 0 и 1,
границы int32, EOF, CRLF, ошибки ввода, слишком длинная строка, пути с
кириллицей и кавычками, перезапись, отсутствующий каталог, отсутствие child
и поток из 1000 составных чисел. Проверяются файл, код завершения и таймаут.

Проверено 10.10.2026 в Ubuntu 24.04.5 LTS под WSL 2: GCC 13.3.0, Python 3.12.3.
Сборка прошла без предупреждений, все 23 интеграционных теста успешны.
Протокол сохранён в tests/results.txt.

Для запуска установленной Ubuntu из PowerShell: `wsl -d Ubuntu-24.04`.
